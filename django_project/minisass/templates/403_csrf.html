{% comment %} Rendered by django.views.csrf.csrf_failure when a POST arrives without a valid CSRF token. Previously absent, so Django used its built-in developer-facing page, which opens with "Forbidden (403) CSRF verification failed. Request aborted." and then explains cookie behaviour to someone who only wanted to reset their password. In practice this is the most common of these pages: it fires whenever a form sits open long enough for the token to expire, which is exactly what happens when someone opens the reset form and goes to find their email. The fix is almost always "reload and submit again", so that is what this page leads with. Django passes a `reason` into the context, but it is deliberately not shown - it describes the CSRF mechanism, not anything the reader can act on.
